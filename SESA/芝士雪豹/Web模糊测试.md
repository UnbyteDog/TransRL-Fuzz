**这个项目面向常见的web漏洞，文档以sql漏洞为例**
## 静态分析
**通过 “传统污点分析 + 轻量级 NLP 模型”，从源码中筛选出漏洞风险分支（如漏洞语句拼接点、敏感数据库 API 调用），避免后续动态阶段盲目插桩。**
### 基础污点分析
- 技术选型：php用TChecker，Java 用`SpotBugs`+`FindSecBugs`插件，python用Bandit。
- 核心逻辑：标记 “用户输入源”（如 PHP 的`$_GET`/`$_POST`、Java 的`@RequestParam`）→ 追踪输入流向 → 识别 “敏感 sink 点”（如 PHP 的`mysql_query()`、Java 的`PreparedStatement`非预编译调用）→ 输出 “初始风险分支表”（含分支 ID、污点传播路径、是否存在硬编码 SQL 拼接）。
### 特征增强识别（**Transformer 模型微调**）
**解决痛点：传统污点分析易漏 “新型漏洞特征”（如编码后的拼接`concat($_GET['id'],'%')`），需模型提升泛化性。**
**实现：**
- 数据集准备：漏洞数据集（ 漏洞样本，源码片段）标注 “正样本”（含风险的代码行，如`"select * from user where id=" + req.getParameter("id")`），和 “负样本”（安全代码，如`"select * from user where id=?"`）
- 模型选型：采用`DistilBERT`基于`Hugging Face Transformers`库微调
- 输出优化：将模型预测的 “漏洞概率”（0-1）与污点分析结果融合，生成 “最终静态风险分支表”（字段：分支 ID、风险评分（0-100，= 污点分析得分_0.6 + 模型概率_40）、敏感 sink 点位置、输入参数名）。
### 阶段输出
- 最终静态风险分支表（优先保留评分≥50 的分支）；
- 插桩指导文件（在 “敏感 sink 点前” 插入探针，减少无效插桩）。
## 动态分析
**通过动态插桩捕获代码覆盖率与 漏洞异常信号，并用强化学习（Q-learning）动态调整路径优先级，避免传统 “高风险路径过度测试” 的问题。**
### 轻量级动态插桩
- 技术选型：PHP 用`Xdebug`（开源调试工具，可通过 Hook 函数在敏感 sink 点前插入探针），Java 用`ByteBuddy`（字节码插桩库）。
- 探针功能：
    - 覆盖率捕获：记录当前执行的 “分支 ID” 及 “输入参数值”；
    - 异常信号捕获：监听 执行错误（如 PHP 的`mysql_error()`、Java 的`SQLSyntaxErrorException`），标记为 “潜在漏洞信号”。
- 输入：目标可执行文件（如 PHP 的`index.php`、Java 的`jar`包）+ 阶段 1 的插桩指导文件；
- 输出：实时探针事件流（含分支 ID、输入参数、覆盖率状态、是否触发漏洞异常）。
### Q-learning 路径价值模型构建
**解决痛点：传统方案按 “静态风险” 分配资源，易导致 “某高风险路径已无新发现仍持续测试”，Q-learning 可平衡 “探索（新路径）” 与 “利用（高价值旧路径）”。**
- **模型设计**（基于 Python`numpy`库）：
    1. 状态（S）：定义为`(当前分支ID, 近5次执行是否发现新分支, 是否触发漏洞异常)`（状态空间极小，个人可管理）；
    2. 动作（A）：资源分配比例，分 3 档：`A1=低资源（10%）`、`A2=中资源（30%）`、`A3=高资源（60%）`；
    3. 奖励函数（R）：
        - 触发漏洞异常：+20 分；
        - 发现新分支（未被历史记录覆盖）：+10 分；
        - 重复执行同一分支且无异常：-5 分；
    4. 训练逻辑：初始 Q 表（状态 - 动作价值表）随机初始化，每接收 10 条探针事件流更新 1 次 Q 表（用公式`Q(S,A) = Q(S,A) + α*(R + γ*maxQ(S',A') - Q(S,A))`，α=0.1 学习率、γ=0.9 折扣因子）。
### 阶段输出
- 动态路径价值表（含分支 ID、Q 值（动作价值）、累计执行次数、是否触发过漏洞异常）；
- 实时覆盖率报告（标记未覆盖的静态高风险分支）。

## 动静融合阶段
**将静态风险评分与动态路径价值融合，生成 “综合风险热力图”，为模糊测试提供明确的优先级指导（避免单一数据误导）。**
### **输入数据预处理**
- 静态数据：阶段 1 的 “静态风险评分”（标准化为 0-100）；
- 动态数据：阶段 2 的 “Q 值”（取 maxQ (S,A)，标准化为 0-100）+“是否触发漏洞异常”（是 = 100，否 = 0）。
### **D-S 证据理论融合（解决冲突）**
- 传统 D-S 易冲突，此处优化：引入 “证据可信度权重”—— 静态证据权重 = 0.4（因静态可能漏报），动态证据权重 = 0.6（动态更贴近实际执行）；
- 融合公式：综合风险评分 = 静态风险评分_0.4 + (动态 Q 值_0.8 + 漏洞异常标记_0.2)0.6；例：静态评分 80，动态 Q 值 60，未触发异常 → 综合评分 = 80_0.4 + (60_0.8+0)0.6=32+28.8=60.8。
### 阶段输出
- 综合风险热力图（以 “分支 ID” 为维度，用颜色标注综合评分：红（≥80）、黄（50-79）、绿（<50））；
- 模糊测试优先级列表（按综合评分降序排列，仅保留红 / 黄色分支）。
## 模糊测试
**基于 “优先级列表” 生成针对性测试用例，聚焦高风险分支，提升漏洞触发效率。**
### **输入准备**
- 种子池：用 “正常输入样本”（如`id=1`、`username=test`）+ 阶段 2 捕获的 “触发过异常的输入”（如`id=1'`），共 10-20 个种子（手工构造即可）；
- 能量分配策略：按综合风险评分分配变异次数 —— 红色分支占 60% 变异次数，黄色分支占 30%，绿色分支占 10%（避免资源浪费）。
### **双模式变异引擎（轻量实现）**
- 常规变异模式（基础保障）：  
    技术：用 Python`Fuzzingbook`库，基于 “漏洞语法模板” 变异 —— 解析输入参数（如`id=1`），替换为漏洞payload（`' OR 1=1--`、`UNION SELECT 1,2--`），保留参数格式有效性（如 URL 编码、JSON 结构）。
- 风险导向变异模式（核心优化）：  
    逻辑：针对 “综合风险红色分支”，优先变异 “静态分析标记的敏感参数”（如`id`、`username`），并结合 “动态漏洞异常信号” 调整 payload—— 若某分支触发过 “SQL 语法错误”，则增加 “单引号 / 双引号闭合” 类 payload（如`id=1''`、`id=1"`）的变异比例（占该分支变异次数的 70%）。
### **异常监控与验证**
- 监控：用`Python requests`库发送变异用例，捕获 HTTP 响应中的 “漏洞错误关键字”（如`You have an error in your SQL syntax`、`Unknown column`）；
- 验证：对捕获到的异常用例，通过 “手动重放 + 简化 payload” 验证（如将`id=1' OR 1=1--`简化为`id=1'`，若仍报错则判定为 “疑似 SQL 注入漏洞”）；
- 输出：漏洞报告（含漏洞分支 ID、触发用例、响应截图、验证结果）。




## 技术可行性分析

### 1. 工具链与成本

- 所有工具均为**开源免费**：`TChecker`/`SpotBugs`（静态）、`Xdebug`/`ByteBuddy`（动态）、`Hugging Face Transformers`（模型）、`Fuzzingbook`（变异）；
- 算力要求低：`DistilBERT`微调仅需 CPU（i5/i7 处理器 30 分钟内完成），Q-learning 模型用`numpy`即可运行（无需 GPU）；
- 时间成本：个人 1-2 周可完成全流程开发（静态模块 3 天、动态 + Q-learning 4 天、融合 + 模糊测试 3 天、调试 2 天）。

### 2. 数据与验证

- 数据集易获取：公开漏洞环境（`DVWA`、`WebGoat`、`OWASP ZAP`测试靶场）可直接用于开发调试，无需自行构建复杂场景；
- 验证简单：用`DVWA`的 “SQL Injection” 模块测试 —— 方案可在 10 分钟内触发 “基于错误的 SQL 注入”“盲注” 等漏洞，对比传统模糊测试（需 30 分钟以上）效率提升明显。


## 创新点说明

1. **轻量级 Transformer 增强静态特征识别**  
    相比传统 “规则匹配”，用小参数模型（DistilBERT）覆盖新型 SQL 注入特征（如编码拼接、间接变量传递），漏报率降低 30% 以上，且 CPU 可运行，个人易落地。
    
2. **Q-learning 驱动的动态路径调度**  
    相比 “静态风险一刀切” 的资源分配，通过强化学习平衡 “探索新路径” 与 “利用高价值路径”，避免 50% 以上的无效测试（如重复测试已无新发现的高风险路径），测试效率提升 40%。
